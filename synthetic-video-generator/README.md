# LineSight Synth

Локальный генератор: фото → карта глубины + параллакс / панорама → MP4 + покадровая разметка.

## Быстрый запуск: без модели глубины

Требуется Python 3.12. Выполняйте команды из папки генератора.
Создайте виртуальное окружение и активируйте его для своей оболочки.

```sh
python -m venv .venv
# Активация PowerShell: .venv/Scripts/Activate.ps1
# Активация bash/zsh: source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Откройте http://127.0.0.1:8765. Работают «Спокойный подвес», «Дрон», классическая
панорама, разметка, общий план, шум и размытие. Для первого запуска достаточно
собственного фото и нарисованного bbox: никакой датасет скачивать не требуется.
FFmpeg входит в imageio-ffmpeg. Сервер локальный, рассчитан на одного пользователя;
он не предназначен для публичного многопользовательского размещения.

## Дополнительно: глубина и параллакс

```sh
python -m pip install -r requirements-depth.txt
python setup_depth.py
python app.py
```

Этот файл включает базовые зависимости и фиксирует также транзитивные зависимости.
Устанавливается CPU-сборка PyTorch из официального индекса PyTorch; рендеринг
параллакса требует OpenGL 3.3 и совместимый видеодрайвер.
CUDA не требуется для оценки глубины. Доступность закреплённых сборок пакетов
зависит от ОС и архитектуры. CUDA-сборка PyTorch устанавливается отдельно.

Модель скачивается однократно: ревизия закреплена в `setup_depth.MODEL_REVISION`,
а фактически используемая ревизия записывается в `models/.../provenance.json`.
Интернет нужен для установки и скачивания весов; фотографии обрабатываются локально.
При обновлении зависимостей или модели повторяйте тесты и проверяйте примеры видео.
Файлы requirements фиксируют версии, но не являются lock-файлами с хешами артефактов.

## Использование

1. Загрузить фото, ввести название дефекта и нарисовать рамку.
2. Можно добавить несколько рамок, ввести координаты вручную или загрузить JSON / Pascal VOC XML. Фото и разметку можно перетащить вместе на страницу; разметку отдельно — на фото или в область импорта. При добавлении нового фото старые рамки очищаются, импорт разметки добавляет рамки.
3. Выбрать профиль камеры, длительность, разрешение, FPS, seed и нажать «Создать видео».
4. Скачать ZIP или отдельные файлы.

Входной JSON (bbox — **xyxy в пикселях исходного фото после EXIF-поворота**):

```json
{"objects":[{"label":"Повреждение изолятора","bbox":[700,250,800,350]}]}
```

## Результат

- `video.mp4`: H.264, yuv420p, постоянный FPS, без нарисованных рамок.
- `annotations.json`: параметры, SHA256 нормализованного исходника, фактические декодированные размеры/FPS/число кадров, длительность, классы, ключевые кадры и интервалы видимости.
- `tracks.jsonl`: строка на каждый кадр, номер с нуля, время в секундах, crop_xywh исходника, объекты. `bbox` — нормализованный xyxy, `bbox_xyxy_px` — пиксели видео. Для невидимого объекта обе рамки null; объект сохраняет ID.
- `keyframes/object_N.png`: кадры, извлечённые из окончательного MP4.

Геометрический рейтинг ключевого кадра: доля видимости × квадратный корень из относительной видимой площади (для плоского режима — площади рамки). При равенстве выбирается первый кадр. Это оценка пригодности по геометрии, не оценка резкости нейросетью. Опциональные шум и размытие применяются после геометрического рендеринга; рейтинг ключевого кадра учитывает их силу. Рамки точны для заданных преобразований исходных областей; семантическая корректность исходной разметки остаётся ответственностью пользователя.

## Глубина и параллакс

В UI по умолчанию выбран «Дрон · спокойный подвес». Для глубины выберите «3D глубина + параллакс». Сила движения регулируется. На крупных планах перемещение камеры автоматически уменьшается, чтобы зум не усиливал артефакты открывающегося фона. Сначала рекомендуем 5 секунд и 720p.

1. **[Depth Anything V2 Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Small-hf)** (`depth-anything/Depth-Anything-V2-Small-hf`, Apache-2.0) локально оценивает относительную обратную глубину. Белое — ближе, чёрное — дальше, это не метры. Модель скачивается в `models/`, точная ревизия записывается в `provenance.json`; используются только safetensors и локальные файлы. Фото не отправляется в сеть. Карта кэшируется по фото и ревизии модели в `.cache/depth/`.
2. Внутри bbox и небольшого запаса вокруг них глубина делается постоянной. Пересекающиеся bbox объединяются для защиты геометрии. RGB дефекта не перерисовывается.
3. Глубина стабилизируется в **три слоя**. Каждый слой имеет собственную глубину и движется с разной экранной скоростью при перемещении 3D-камеры. Это многослойная 2.5D-реконструкция: выбранный компромисс сохраняет форму мелких дефектов и устраняет растянутые поверхности на резких границах глубины. При недостаточном разнообразии глубины слоёв может быть меньше.
4. Скрытые области нижних слоёв заполняются один раз алгоритмом OpenCV Telea. Это предположение о фоне, не достоверная реконструкция. В собственном слое каждый дефект сохраняет исходную текстуру. Заполненные пиксели имеют отдельный признак происхождения и **не создают bbox**.
5. GPU рендерит слои с Z-буфером, поэтому более близкие участки перекрывают дальние. Вместе с цветом записываются координаты исходных пикселей. Bbox вычисляется по реально видимой части исходной прямоугольной области, а не по одной матрице на весь кадр.
6. Ключевой кадр должен содержать ≥95% проекции исходной области, минимум 16 пикселей и ≤1% геометрически неопределённых пикселей. Если подходящего кадра нет, `keyframe=null` и есть предупреждение. Такую находку нельзя выдавать за полноценный эталон.

Исходная bbox — прямоугольная область, а не маска сегментации: фон внутри неё также считается частью размеченной области. Результат гарантирует перенос этой разметки относительно рендера, но не точность восстановленной физической геометрии. Тонкие провода, стекло и границы оборудования могут иметь ошибки глубины/разделения слоёв; открывшийся фон может быть размыт. Нельзя получить достоверный большой облёт и обратную сторону объекта из единственного фото. Для этого нужны дополнительные ракурсы или полноценная 3D-сцена.

Дополнительные файлы в ZIP:

- `depth_raw.png` / `.npy`: исходная нормализованная оценка обратной глубины; PNG 16 bit, NPY float32.
- `depth_effective.png` / `.npy`: стабилизированная карта слоёв, использованная для рендеринга.
- `depth_protected.png`: области, защищённые от деформации.
- `depth_metadata.json`: модель, ревизия, размер сетки, рендерер, запрошенная/фактическая амплитуда, предупреждения.
- `keyframes/object_N_original_mask.png`: белое — исходные пиксели, чёрное — восстановленный фон в ключевом кадре; маска относится к рендеру до видеосжатия.

`tracks.jsonl` дополнительно содержит `camera_3d` (позиция, вращение, внутренние параметры камеры) и `reconstructed_fraction`. У объектов есть `visible_pixels`, `occluded_fraction`, `keyframe_eligible`, `projected_source_bbox_polygon`. `visible_fraction` — отношение реально видимых исходных пикселей к полной проекции bbox; `occluded_fraction` отделяет перекрытие от выхода за границы кадра. Ключевые кадры извлекаются из окончательного MP4. Кадры с восстановленным фоном пригодны для тестов пайплайна, но не заменяют реальные положительные примеры.

## Маршруты «Спокойный подвес» и «Дрон»

### Дополнительные точки осмотра (опционально)

В поле «Что отмечаем следующей рамкой» выберите «Точка осмотра» и нарисуйте рамки других элементов конструкции. Зелёные рамки — дефекты, оранжевые — дополнительные точки. Название дополнительной точки необязательно. Кнопки «В точку» / «В дефект» меняют назначение существующей рамки, включая импортированную. Нужен хотя бы один дефект. Переключатель «Облетать дополнительные точки осмотра» позволяет временно отключить точки без удаления.

При активных точках используется `focus-flight-v1` во всех профилях: камера посещает **все** дефекты и дополнительные точки, фиксируя каждую две секунды. Между ними — плавные переходы с зумом; для перспективных профилей добавляются мягкие повороты по пути. Случайных целей за пределами выбранных элементов нет. Seed меняет порядок и длительность переходов; при двух и более дополнительных точках начало и конец отдаются им. В режиме глубины параллакс плавно убирается на фиксациях для сохранения точного кадрирования.

На маршрут нужно минимум 4 секунды × общее число рамок (например, дефект + 2 точки = минимум 12 секунд). Иначе запрос отклоняется с пояснением: точки не пропускаются и видео не ускоряется. До 14 дополнительных точек, длительность до 180 секунд. Слишком большие рамки, не помещающиеся в 16:9, отклоняются. Если дополнительная точка близка к дефекту или перекрывает его, полное исчезновение дефекта из кадра не гарантируется — выводится предупреждение.

Дополнительные точки **не являются разметкой дефектов** и не добавляются в покадровый `objects`. В `annotations.json` есть отдельные `focus_points` и `focus_visits` с таймкодом, интервалом фиксации и рамкой в кадре. Середина каждой фиксации проверяется на полноту кадрирования (не менее 98%). Для режима глубины это проверка кадрирования в исходном ракурсе, а не подтверждение реального состояния оборудования.

JSON может содержать оба массива (или только дополнительные точки при импорте в уже размеченное фото):

```json
{
  "objects": [{"label": "Повреждение", "bbox": [700,250,800,350]}],
  "focus_points": [{"label": "Соседний изолятор", "bbox": [100,100,200,250]}]
}
```

Все координаты — xyxy в пикселях исходного фото. XML по умолчанию импортирует дефекты; назначение можно поменять кнопкой «В точку». Без активных дополнительных точек прежний планировщик работает как раньше.

Эти два профиля используют планировщик `flight-v1`. Он выбирает боковые/диагональные проходы, набор и снижение высоты, самостоятельные горизонтальные повороты камеры (yaw), вертикальные наклоны (pitch), приближение/отдаление и редкие зависания. Дефекты проходят через кадр со смещённой композицией, а не всегда остаются в центре. Yaw — вращение вокруг вертикальной оси; он не заменяется вращением плоского изображения (roll).

Seed управляет начальной областью, порядком манёвров, направлениями, масштабами, длительностями и порядком осмотра объектов. Кнопка «Другой маршрут» выбирает новый seed; видео создаётся после нажатия «Создать видео». При одинаковых фото, разметке, длительности, профиле и seed маршрут повторяется. Физическое движение не зависит от FPS: в одинаковые моменты времени положение камеры одинаковое.

Координаты, логарифм масштаба и три угла интерполируются квинтическими кривыми с непрерывными положением, скоростью и ускорением. Внутренние точки сохраняют инерционную скорость; полный тормоз на каждой точке не обязателен. Zoom интерполируется отдельно без лишних скачков масштаба. У спокойного подвеса микроколебания слабее. На границах исходника фактическое преобразование ограничивается доступной областью.

При большом количестве дефектов короткого видео может не хватить для отдельных медленных проходов всех объектов. В план включается не больше одного целевого прохода на шесть секунд (минимум один), остальные объекты по-прежнему размечаются при появлении в кадре. Если часть объектов не получила отдельного прохода, UI показывает предупреждение. Для полного осмотра увеличьте длительность или разделите набор объектов.

`flight_plan.json` в ZIP содержит версию планировщика, тайминги и параметры движения. `tracks.jsonl` сохраняет `flight_motion` и фактическую матрицу `source_to_frame_matrix`; bbox вычисляется по этой же матрице. «Классическая панорама» и режим глубины сохраняют собственную прежнюю последовательность осмотра.

Режимы «Дрон», «Спокойный подвес», «Классическая панорама» используют **одну плоскость**, без параллакса. Режим глубины описан выше. Камера ограничивается границами исходника; в режиме глубины амплитуда предварительно проверяется и при необходимости уменьшается, что отражается в метаданных. Каждый готовый кадр также проверяется на неизвестные пиксели за краями фото; при их появлении генерация завершается ошибкой, не подменяя их фоном. Большой дефект может оставаться видимым весь ролик. Портретное фото обрезается до 16:9; маленькие фото могут увеличиваться.

В перспективном режиме `source_to_frame_matrix` хранит матрицу преобразования исходника в кадр. Исходные bbox преобразуются в четырёхугольники, обрезаются по кадру и только затем превращаются в охватывающие bbox. Дополнительно сохраняются `polygon_xy_px` и `visible_polygon_xy_px`; доля видимости вычисляется по площади полигона. Рамка охватывает преобразованную исходную разметку, а не точную сегментационную маску дефекта.

### Pascal VOC XML

Поддерживаются `annotation/size`, любое число `object/name` и `object/bndbox/{xmin,ymin,xmax,ymax}` (до 100 объектов). Размеры XML должны совпадать с отображаемым фото, иначе импорт отклоняется. `folder`, `path`, `pose`, `difficult`, `truncated` не влияют на импорт; все объекты включаются. Координаты сохраняются как заданы, без автоматического сдвига −1 (варианты VOC отличаются соглашениями об индексации). Импорт не масштабирует и не поворачивает рамки автоматически. Для фото с EXIF-поворотом XML должен соответствовать отображаемому изображению. XML не больше 2 МБ, без DTD/ENTITY. Названия классов, например `nw`, сохраняются без перевода.

## Производительность и хранение

Плоские режимы: Pillow-рендеринг на CPU. Глубина: локальный PyTorch и GPU-рендеринг слоёв. Кодирование: FFmpeg/libx264 ultrafast CRF 18. Расчёт глубины кэшируется, а дополнительный проход видимости выполняется для каждого дефекта; время зависит от разрешения и числа объектов. Для быстрых проб используйте 640×360 / 15 FPS / 5 с. После кодирования видео полностью декодируется для проверки количества кадров и извлечения ключевых кадров; этот этап включён в generation_seconds, упаковка ZIP — нет.

Одна задача одновременно; прогресс хранится в памяти. При перезапуске незавершённые задачи не восстанавливаются. Результаты и нормализованные исходники остаются в `output/<job_id>/`; удаляйте ненужные папки вручную. Папка исключена из Git. ZIP не содержит исходное фото.

## Проверка

Базовые тесты без установки глубины:

```sh
python scripts/check_base.py
```

Полный набор (после установки requirements-depth.txt, требует OpenGL):

```sh
python -m unittest discover -s tests -v
```

Проверяются преобразование/обрезание bbox, границы и воспроизводимость траекторий, XML, валидация, реальное кодирование/декодирование MP4, соответствие ключевого кадра разметке, разная скорость слоёв, перекрытие дальнего дефекта ближним и сохранение исходного цвета размеченных пикселей. Тесты рендеринга глубины требуют зависимостей из requirements-depth.txt и OpenGL; модель в юнит-тестах подменяется фиксированной картой глубины, для проверки реальной модели требуется генерация в режиме глубины.


### Длительные видео, общий план и эффекты съёмки

UI поддерживает 120 и 180 секунд; API — от 1 до 180. Флажок «Добавить общий план» добавляет отдельную цель существующего маршрута с фиксацией 2 секунды. Это не дефект: в `focus_visits` и плане она имеет `target_kind: overview` / `kind: overview`. Общий план использует максимальную вписанную область 16:9. Если она покрывает меньше 90% площади фото, запрос отклоняется с пояснением (поля и дорисовка за границами не добавляются). Дополнительная пользовательская рамка также может занимать всю вписанную область — прежний предел 95% снят. При включённом общем плане требуется минимум 4 секунды на каждую цель, включая дефекты и активные точки.

`blur_strength` и `noise_strength`: числа от 0 до 1, по умолчанию 0. Эффекты применяются после геометрического рендеринга, до кодирования MP4. Короткие плавные эпизоды связаны с движением/зумом: размытие имитирует небольшую расфокусировку и смаз вдоль движения, шум преимущественно яркостный, сильнее в тенях. Это художественная модель съёмки, не калиброванная модель конкретной камеры. Seed делает эпизоды повторяемыми.

В каждой строке tracks.jsonl поле `capture_effects` содержит `blur_radius_px` (номинальный масштаб размытия), `noise_sigma_255` (базовая сигма яркостного шума в шкале 0–255), `motion_activity` (0–1). Bbox остаётся геометрической рамкой исходной области: размытие не расширяет рамку на ореол и не меняет visible_fraction. Ключевые кадры получают штраф: геометрический quality_score делится на `1 + blur_radius_px + noise_sigma_255 / 8`. Эти параметры сохранены также в config. Эффекты отключаются независимо нулевыми ползунками; PNG ключевого кадра извлекается из MP4 уже с эффектами.
