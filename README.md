# LineSight AI

Система интеллектуальной инспекции ЛЭП на основе компьютерного зрения. Тестовый MVP (1–9 ноября 2026): принимает видео облёта, находит объекты и проблемные участки, инженер подтверждает находки и получает PDF-отчёт на русском.

Система не ставит диагноз и не заменяет инженера: решение всегда за человеком.

## Структура

| Папка | Что внутри |
| --- | --- |
| `backend/` | FastAPI: API, БД, хранилище, воркер (очередь в Postgres) |
| `frontend/` | Next.js + TypeScript + Tailwind, тёмная тема |
| `ml/` | Предобработка, детекция, трекинг, находки, обучение, синтетика |
| `data/` | Видео, кадры, веса, демо-данные (в git не попадает) |
| `docs/` | Архитектура и заметки |

Подробнее: [docs/architecture.md](docs/architecture.md).

## Контракт

Единственный источник правды для фронтенда и бэкенда. Все эндпоинты, кроме `POST /api/login`, требуют заголовок `Authorization: Bearer <token>`; без него или с просроченным токеном ответ `401`.

### Статусы инспекции

`queued → processing → done | failed`

При `failed` заполняется `error_code`:

| Код | Когда |
| --- | --- |
| `E_VIDEO_INVALID` | файл не открывается как видео |
| `E_DECODE` | ошибка декодирования кадров |
| `E_MODEL` | нет весов или сбой инференса |
| `E_TIMEOUT` | превышен лимит времени задачи |

### Находка (Finding)

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | uuid | идентификатор |
| `type` | string | тип: `low_visibility` или класс объекта/дефекта |
| `priority` | `high` \| `medium` \| `low` \| `insufficient_data` | приоритет |
| `confidence` | float 0–1 | уверенность |
| `timecode_sec` | float | таймкод в секундах |
| `frame_path` | string \| null | относительный путь к ключевому кадру |
| `bbox` | `{x, y, w, h}` \| null | рамка в долях 0–1 от кадра (`x`, `y` — левый верхний угол) |
| `status` | `new` \| `confirmed` \| `rejected` \| `reshoot` | решение инженера |

### Эндпоинты

#### `POST /api/login`

```json
// запрос
```

Ответ `201`:


## Решение Go/No-Go (задача 3)

- **Класс для детекции и трекинга:** все классы подмножества «transmission line object detection» датасета sxiong (оборудование и дефекты ЛЭП, разметка рамками). Редкие классы (меньше 20 примеров) отбрасываются на подготовке датасета.
- **Подстанция (18 классов, маски):** не берём в MVP, возможное расширение после приёмки.
- **Обучение:** запускает тимлид в Colab/Kaggle или на локальной GPU по ноутбуку `ml/notebooks/train_colab.ipynb`; готовые `best.pt` и `metrics.json` кладутся в `data/weights/`. Пока весов нет, воркер находит только «недостаточную видимость».
- **Первое обучение (задача 45):** YOLOv8s, 40 эпох, imgsz 640, 14 классов (после отсева редких), 7573 изображения в train и 1893 в val. На валидации **mAP50 = 0.603**, **mAP50-95 = 0.253**. Веса `best.pt` (~21 МБ) лежат в `data/weights/best.pt`; в ветке `asyl_experiment` они загружены вручную (обычно `*.pt` и `data/` в `.gitignore`), при дообучении версию весов лучше хранить через Release или Drive.
- **Классы модели:** все 14 — дефекты или опасные объекты (разрядник, опорный изолятор, провод, арматура, гнездо, посторонний предмет). Обычного «изолятора» или «опоры» среди них нет. Самые редкие классы (`jj_jxps`, `blq_yxdk`: по 16 примеров в train, `yxdk`: 36) модель, скорее всего, распознаёт плохо.
- **Проверка на реальных изображениях (4 ноября):** 11 снимков гирлянд изоляторов (`data/eval/real_images/`), порог уверенности 0,25. Из 9 снимков со сколами модель что-то нашла на 3 (33%), ложных срабатываний на снимке без дефекта 0 из 1 (выборка мала). Уверенность низкая: 0,31 на двух снимках, 0,66 на одном. На `img01` рамка стоит на сколе (`czjyz_ps`), на `img02` рамка рядом, но не на сколе и класс другой (`blq_jyjc`). **Порог 70% не пройден.** Причина вероятна в сдвиге домена: в обучении опорные изоляторы, на снимках подвесные гирлянды.
- **Порог 70%:** доля кадров, где объект найден верно, считается на 20–30 размеченных кадрах (`ml/check_detector.py`, `ml/evaluate.py`); итог записать сюда после первого обучения.

### Видео для проверки и демо

| Файл | Что на видео | Источник | Лицензия |
| --- | --- | --- | --- |
| `data/demo/real/real_substation_30s.mp4` (30 с, 1080×1080) | подстанция: изоляторы и разрядники на ферме | YouTube, канал [@chsrao18](https://www.youtube.com/@chsrao18) | не проверена; тимлид разрешил хранить в репозитории, использовать только для внутренней приёмки |
| `data/demo/real/real_tower_22s.mp4` (22 с, 1080×1080) | опора ЛЭП с гирляндой подвесных изоляторов | YouTube, канал [@chsrao18](https://www.youtube.com/@chsrao18) | не проверена; тимлид разрешил хранить в репозитории, использовать только для внутренней приёмки |

На обоих видео нет видимых дефектов: они проверяют ложные срабатывания модели, а не полноту. Для публичного показа или коммерческого использования условия лицензии канала нужно уточнить.

### Изображения для проверки модели

| Папка | Что внутри | Источник | Лицензия |
| --- | --- | --- | --- |
| `data/eval/real_images/` (11 снимков, `labels.json`) | гирлянды изоляторов: 9 со сколами тарелок, 1 спорный, 1 без дефекта | Kaggle: [ramgolla17042006/insulator-defect-detection](https://www.kaggle.com/datasets/ramgolla17042006/insulator-defect-detection) | не указана на странице; тимлид разрешил хранить в репозитории, использовать только для внутренней проверки |

Разметка в `labels.json` сделана по внешнему виду, не экспертом. Это тестовая выборка: обучать на ней нельзя, иначе проверка теряет смысл. Запуск: `python -m ml.check_images data/weights/best.pt data/eval/real_images`.
